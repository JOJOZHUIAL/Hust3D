# 内网穿透部署（Windows 本机 · 最快对外访问）

无需云服务器、无需域名备案，用第三方隧道把本机 Flask 服务（5000 端口）暴露到公网，
几分钟即可让外部访问。适合**演示、社团内部短期使用**；长期正式运营仍建议迁移到
云服务器（见 `deploy/README.md`）。

## 原理

```
外部用户 ──> cpolar 公网隧道 ──> 本机 127.0.0.1:5000（Flask）
                                   ├── /           前端页面（构建产物 dist/）
                                   ├── /api/*      后端接口
                                   └── /uploads/*  上传文件（STL/签名/反馈图）
```

后端已改造为**单端口服务整站**：`app.py` 兜底服务 `frontend/dist/` 静态资源并回退到
`index.html`（SPA），因此只需一条隧道指向 5000，无需暴露前端 dev server。

---

## 一、准备（一次性）

1. **确保后端已启动**并监听 `0.0.0.0:5000`：

   ```bash
   cd backend
   .venv\Scripts\activate          # Windows 虚拟环境
   python app.py                    # 默认 http://0.0.0.0:5000
   ```

   > 对外访问时 **debug 已默认关闭**（安全，见「安全注意」）。确认日志出现
   > `Debug mode: off`。

2. **前端先构建一次**（后端服务的正是 `frontend/dist/`）：

   ```bash
   cd frontend
   npm run build                    # 产出 dist/
   ```

   > 每次改完前端代码，都要重新 `npm run build` 并重启后端才会生效。

---

## 二、安装并启动 cpolar 隧道

> 任选一款内网穿透工具即可，这里以 **cpolar**（国内、免费、中文）为例。

1. **注册**：访问 https://www.cpolar.com 注册账号（需手机号）。
2. **下载 Windows 客户端**：https://www.cpolar.com/download ，解压得到 `cpolar.exe`。
3. **登录**（首次，绑定账号）：控制台里找到你的 **authtoken**，运行：

   ```bash
   cpolar.exe authtoken <你的authtoken>
   ```

4. **创建隧道**（把本机 5000 暴露出去）：

   ```bash
   cpolar.exe http 5000
   ```

   终端会打印类似：

   ```
   Tunnel Status  online
   Forwarding     https://xxxxx.r2.cpolar.top -> http://localhost:5000
   ```

5. **用手机 / 他人电脑访问**上面那个 `https://xxxxx.r2.cpolar.top` 地址即可打开网站。

> 免费版隧道域名是**随机分配的，重启 cpolar 后可能变化**；需要固定域名可升级套餐，
> 或在 cpolar 控制台申请免费二级子域名（视当时政策）。

## 三、上线前检查

- [ ] 后端日志显示 `Debug mode: off`（已默认关闭，公网必须关闭 debug）
- [ ] `backend/.env` 中 `SECRET_KEY`、`JWT_SECRET` 已改为随机值
- [ ] `CAS_MOCK=0`（已接入真实教务系统；若尚未联调可暂留 1 仅供演示）
- [ ] `ADMIN_STUDENT_IDS` 已配置正确的管理员学号
- [ ] 上传目录 `backend/uploads` 可写

---

## 四、安全注意

1. **必须关闭 debug**：Werkzeug 交互式调试器暴露公网可执行任意代码。后端已默认
   `debug=False`，仅当显式 `FLASK_DEBUG=1` 才开启——对外时切勿设置该变量。
2. **密码传输必须 HTTPS**：登录走教务系统学号+密码。cpolar 免费隧道默认即提供
   `https://` 地址，**务必使用 https 链接**访问，勿用 http。
3. **验证码会话在进程内存**：内网穿透下单进程 `python app.py` 运行无问题；若日后改
   多进程（gunicorn -w N）需迁移 Redis，否则验证码会因请求落到不同进程而校验失败。
4. **生产密钥**：`backend/.env` 的 `SECRET_KEY`/`JWT_SECRET` 仍为开发占位值，正式使用
   前请替换为随机长字符串（可用 `python -c "import secrets; print(secrets.token_hex(32))"` 生成）。

---

## 五、常见问题

| 现象 | 处理 |
| --- | --- |
| 打开隧道地址白屏 | 前端未构建或构建过期：`cd frontend && npm run build` 后重启后端 |
| 静态资源 MIME 报错 | 已修复（app.py 强制 .js/.mjs 为 text/javascript） |
| 登录验证码刷不出 | 确认 `CAS_MOCK=0` 且本机能访问教务系统 jwzx.hrbust.edu.cn |
| cpolar 隧道地址变了 | 免费版正常现象，用终端最新打印的 Forwarding 地址 |
