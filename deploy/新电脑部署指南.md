# 新电脑部署指南（Windows）

把项目拷到另一台电脑后无法启动，通常卡在三类问题：
**虚拟环境不可移植**、**依赖没装全/装错包**、**MySQL 账号与库不存在**。
本指南按顺序做完即可跑通。

---

## 0. 为什么拷过去的 `.venv` 不能用

`.venv` 里的启动器**写死了创建它的那台电脑的 Python 路径**
（如 `C:\Users\ROG\AppData\...\python.exe`），换电脑后必然报：

```
did not find executable at 'C:\Users\ROG\...\python.exe'
```

**虚拟环境永远不要拷贝，必须在新电脑上重建。**
如果已经把 `.venv` 拷过去了，先删掉它：

```bat
cd /d D:\hust3d\backend
rmdir /s /q .venv
```

## 2. 后端安装（一键脚本）

双击运行 `backend\scripts\setup_backend.bat`，它做两件事：
创建 `.venv` 虚拟环境 + 用**清华镜像**安装 `requirements-win.txt` 全部依赖。

或手动执行：

```bat
cd /d D:\hust3d\backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-win.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> **pip 网络异常/超时**：换镜像源即可——
> 阿里：`-i https://mirrors.aliyun.com/pypi/simple/`
> 腾讯：`-i https://mirrors.cloud.tencent.com/pypi/simple`

> ⚠️ **不要手敲 `pip install jwt` 或 `pip install docx`**——这是两个同名的错误旧包！
> 正确的是 `PyJWT` 和 `python-docx`（requirements 里已写对）。如果误装过，执行：
>
> ```bat
> .venv\Scripts\python.exe -m pip uninstall -y jwt docx
> .venv\Scripts\python.exe -m pip install -r requirements-win.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
> ```

## 3. 配置 MySQL（解决 1045 Access denied）

新电脑的 MySQL 里**没有** `.env` 里写的账号（如 `hust3d`），登录会报
`1045 Access denied for user 'hust3d'@'localhost'`。二选一：

**方案 A：按 .env 的账号在 MySQL 里建号**（.env 不用改，推荐）

编辑 `deploy\mysql_init.sql`，把里面的 `'YourPassword123'` 替换成
`backend\.env` 中 `DB_PASSWORD` 的值，然后用 root 执行一次：

```bat
cd /d D:\hust3d\backend
mysql -uroot -p < ..\deploy\mysql_init.sql
```

**方案 B：改 `.env` 用本机 root**

编辑 `backend\.env`：

```
DB_USER=root
DB_PASSWORD=本机root密码
```

> 验证账号是否可用：`mysql -h 127.0.0.1 -u hust3d -p hust_3d`，
> 能登进去说明账号没问题（报 1045 就是账号/密码不对）。

**建表**：后端启动时会**自动补建缺失的表**（`db.create_all`，只建缺的、不动已有结构），
所以直接启动即可，无需手动执行 schema.sql。完整建表脚本仍保留在 `sql\schema.sql` 供查阅。

## 4. 启动

```bat
cd /d D:\hust3d\backend
.venv\Scripts\python.exe app.py
```

看到 `Running on http://127.0.0.1:5000` 即成功。
浏览器访问 `http://localhost:5000`（前端已包含 `frontend\dist` 构建产物，无需 npm）。

局域网其他电脑/手机访问 `http://本机IP:5000`（后端已监听 0.0.0.0；若连不上，在 Windows 防火墙放行 5000 端口）。

## 5. 快速自检（可选，不依赖 MySQL）

不配数据库也能验证后端是否能跑（SQLite + 教务 mock）：

```bat
cd /d D:\hust3d\backend
set DATABASE_URL=sqlite:///./smoke.db
set CAS_MOCK=1
set ADMIN_STUDENT_IDS=20260001
.venv\Scripts\python.exe scripts\smoke_test.py
```

全部 PASS 说明虚拟环境和依赖没问题，剩下就是 MySQL 配置。

## 6. 常见错误速查

| 报错 | 原因 | 处理 |
|---|---|---|
| `did not find executable at 'C:\Users\xx\...\python.exe'` | 拷贝了旧电脑的 `.venv` | 删除 `.venv`，按第 2 节重建 |
| `ModuleNotFoundError: No module named 'flask'` | 用了全局 Python，未装依赖 | 用 `.venv\Scripts\python.exe` 启动，或先装依赖 |
| `No module named 'exceptions'`（来自 docx.py） | 误装了 `docx` 旧包 | `pip uninstall -y docx` 后装 `python-docx` |
| `module 'jwt' has no attribute ...` / token 异常 | 误装了 `jwt` 旧包 | `pip uninstall -y jwt` 后装 `PyJWT` |
| pip 下载超时 / 网络异常 | 官方源在国内不稳定 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| `1045 Access denied for user 'hust3d'@'localhost'` | 新机 MySQL 无此账号/密码不符 | 按第 3 节执行 `mysql_init.sql` 或改 `.env` 用 root |
| `2003 Can't connect to MySQL` | MySQL 服务未启动 | 服务里启动 MySQL80，或安装 MySQL |
| 页面能开但登录报"网络异常" | 后端没起 / 数据库连不上 | 看后端窗口的报错日志 |

## 7. 开发模式（可选）

需要改前端代码时才需要：

```bat
cd /d D:\hust3d\frontend
npm install
npm run dev     REM 开发地址 http://localhost:5173，已代理 /api 到 5000
```

只做日常使用时，`frontend\dist` + 后端 5000 端口即可，无需 Node。
